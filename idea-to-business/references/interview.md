# 分页多选访谈

## 使用

先基于最新记录设计问题，不固定模板问完整套。配置为 UTF-8 JSON：

```json
{
  "schema": "example-project-interview-r1-v1",
  "round": 1,
  "title": "项目想法访谈",
  "followup": "请更新本项目需求理解，识别下一步关键缺口；尚未确认需求时不要进入正式研究。",
  "questions": [
    {"title": "哪些使用场景与你的想法接近？", "options": ["场景甲", "场景乙"], "hint": "可同时选择，或自行补充。"}
  ]
}
```

执行 `python scripts/render_interview.py <config.json> <absolute-output.html>`。使用当前运行时，不硬编码某台电脑的 Python 路径。生成的文件是内嵌片段，输出目录用当前任务的持久可读路径；有 visualize 技能时先完整读取并按其契约展示，不给用户只展示 HTML 源码。

每个项目/轮次的 schema 必须唯一，改变问题和选项含义时增加 schema 版本；同一 schema 不重排选项。生成器默认不覆盖已有文件，修改已存在表单要明确使用 `--overwrite`，防止丢失在填答案。

配置问题数量 1–4，均可多选和补充；不确定可跳过。相互排斥的回答进入模型后由代理解释矛盾、提出组合建议，不由表单擅自取消用户选项。提交是用户按钮触发的当前聊天消息，不会发到其他聊天。

## 输入与状态

模板保留实测修复：中文组合输入结束再保存；延迟保存、独立快照、顺序保存；忽略自身状态回传；当前本地编辑优先，不因迟到状态重建焦点文本框；翻页保留回答；汇总前可返回修改。

状态只放选择和有限补充，限制 UTF-8 总大小低于 16 KiB；超出时提示复制回答，不宣称保存成功。补充默认最多 1000 字，长材料可直接发聊天。状态快照不是提交；submit 实际消息才是回答记录，丢失时接受用户粘贴。

不要在表单自动预填代理推断，不在后台自动提交，不为测试向真实聊天发送虚构答案。结构检查不等于用户客户端体验验收。
