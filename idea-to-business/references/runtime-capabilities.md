# 运行能力快照

记录日期：2026-10-15；2026-10-17 补充普通 Chat 网页实测。只适用于本次桌面环境，正式使用需要刷新。

- list_threads 早期测试识别了三个已授权 ChatGPT 聊天。实际使用时刷新能力；不能假设后续版本仍支持同样的读取渠道。
- read_thread 早期测试读到用户消息和三个附件元数据；返回内容明确未包含附件图片本身，不能由元数据推断原图内容或图像生成归属。
- 一次无生图连通测试的 send_message_to_thread 返回聊天编号；首次回读尚未出现消息，第二次回读观察到同一测试编号的用户消息及 completed 状态。发送已证实。助手回复仅返回 chatgpt-content-reference 占位引用，回复正文未包含在工具结果中，不能认为完整内容读取通过。
- 用户自行登录普通 Chat 网页后，已读取连通测试的完整回复，并取回、查看过一张旧生成图。旧图只用于读取验证，不计入新轮次。
- 2026-10-17 普通 Chat 五版流程图试跑仅点击发送一次；发送调用后的快照超时，恢复只读后观察到同编号消息和生成中状态，随后当前回复显示五个图像切换项及回复完成。发送与五图生成已核验。查看器打开的新图显示 V1 标签；没有触发重新生成。
- 本次新五图原件自动取回未通过：下载事件、已显示图像 downloadMedia、原生复制后剪贴板读取均超时。后续外部浏览器下载观察也超时，Windows Computer Use 因网址识别不可靠停止。恢复清单未再列出该外部浏览器。内置浏览器页面资产清单 image 数为 0，查看器图片使用 blob URL。浏览器资源检查也超时。查看器截图不能当作原图，不能绕过工具安全限制。
- 用户下载并附回五原件后，代理从实际下载目录自动收集同一批文件，五个字节哈希均与用户对应附件一致。五图都能完整解码，保留原字节；重复导入核对通过。下载目录收集成功不等于网页自动下载成功，人工环节仍需如实记录。
- 后续找到并验证替代路径：聊天图片文件菜单“在资料库中打开”后，已显示原件有可访问的 HTTPS 媒体地址；通过浏览器受支持的媒体导出实际取回本轮五张。五图全部与用户对应原件字节哈希一致，并再次完整解码、幂等归档及查看，未重发生图。至此本轮生成后的自动取回通过；前述失败证据保留。
- 直接点击聊天查看器下载按钮会先打开二级菜单；仅打开菜单不会触发下载。选择系列下载菜单项后仍未获得落盘证明，最终使用资料库路径。一张导出调用观察超时但实际文件已落盘，核对后接回。每次浏览器操作延迟明显，尚未证明长期稳定无人值守。
- 逐张原图审核已完成：四版必要正文完整，一版规则句漏“改”字，需确认修正提示词后补图；标题经放大核对为正确文字。用户尚未选版；不能宣布五版全部合格终稿。部分版面采用模型绘制的品牌标志，未核对官方资产，不宣称为官方原图。
- 新增一次性发送状态和五图导入辅助脚本，16 项本地行为回归及实际五图导入通过；这不验证远程点击、渠道额度、图片文字、用户满意或商业有效性。
- 浏览器页面初始绑定读取有超时；通过同一浏览器的已知标签句柄配合 DOM 快照/截图恢复了读取。后续操作仍有不稳定延迟，不把一次发送成功称为稳定全自动。
- 用户补充截图明确显示“聊天/工作”切换器选中“聊天”，生图目标已明确为普通 Chat。官方 Work 与 Codex 共享限制的说明不覆盖普通 Chat 的全部额度规则，不应据此反驳用户的模式区别。截图未核验之前发送工具的实际路由；kind=chatgpt 不能作为自动生图的模式证据。
